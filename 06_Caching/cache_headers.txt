4. EXPLANATION: FRESH CACHE HIT vs CONDITIONAL REQUEST vs FULL REQUEST
--------------------------------------------------------------------------------
- Fresh Cache Hit:
  The client uses a locally cached response that is still considered fresh according
  to its cache policy (e.g., within the `max-age=60` window defined by the
  `Cache-Control` header). No network request is transmitted to the origin server.

- Conditional Request:
  When cached content may be stale or requires validation, the client sends a
  conditional request containing the cached validator (e.g., `If-None-Match: "teamabs-v1"`).
  If the representation on the server has not changed, the server returns an
  `HTTP 304 Not Modified` status with no message body, saving bandwidth and
  server compute while confirming freshness.

- Full New Request:
  The client sends an unconditional request (no cache validator or a mismatched
  validator). The server processes the request and returns a complete `HTTP 200 OK`
  response including all response headers and the full payload body.
